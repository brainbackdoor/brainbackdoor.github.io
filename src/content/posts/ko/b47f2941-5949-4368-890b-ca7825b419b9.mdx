## 1&#46; 서버 살펴보기

<span id="39985184-f92b-4c45-a898-726d9f83a499"></span>

```bash
# 현재 위치를 확인합니다.
$ pwd

# 명령어의 메뉴얼을 확인
$ man pwd

# 파일시스템별 가용공간을 확인합니다.
$ df -h

# 각 디렉토리별로 디스크 사용량을 확인합니다.
$ sudo du -shc /*
# https://ko.wikipedia.org/wiki/Sudo
# du -h : 하위디렉토리까지 표현
# du -sh : 해당 디렉토리만 표현
# du -ah : 파일에 대한 정보도 표현

# 현재 경로의 파일들(숨김파일 포함)의 정보를 확인합니다.
$ ls -al

## 서버의 공인 IP 확인해봅니다.
$ curl wgetip.com

# git 명령어의 위치를 확인해봅니다.
$ which git 

# 스크립트를 활용하여 서버 상세 정보를 확인해봅니다.
## 물리 Storage 정보 조회
## 메모리 갯수 조회
## NIC 정보 조회
## 프로세스별 메모리 사용량 조회
## Routing table 조회
## cron 스케줄 정보 조회
## 방화벽 정보 조회
$ git clone https://github.com/woowacourse/script-practice
$ cd script-practice/script/
$ sudo chmod 755 ./*
$ sudo ./server_resource.sh all


# 소스코드를 관리할 디렉토리를 생성하고 이동합니다.
$ mkdir brainbackdoor && cd brainbackdoor
```

## 2&#46; 파일 다루기

<span id="0814ff5a-fc94-4171-9ef6-f38c04031a0c"></span>

```bash
# GitHub 저장소를 clone해봅니다.
$ git clone https://github.com/brainbackdoor/infra-workshop

# 하위경로까지 복제합니다.
$ cp -R [원본디렉토리] [목적지디렉토리]
$ cp -R ./infra-workshop ../
$ ls -al ../infra-workshop

# 디렉토리의 이름을 변경합니다.
$ mv [원본디렉토리] [목적지디렉토리]
$ mv ../infra-workshop ./infra-bak

# 파일 및 디렉토리를 삭제합니다.
$ rm -rf ./infra-bak 

# 파일 내용을 표준출력해봅니다.
$ cat ./infra-workshop/README.md

# 파일 이름으로 파일을 찾아봅니다. 
$ sudo apt install mlocate
$ sudo updatedb
$ locate build.gradle*
# find ./* -name "*java"
# find . -type f -user root \( -perm 4000 -o -perm -2000 \) -exec ls -al {} \;
# find . -type f -mtime -2 -exec ls -al {} \;
# find . -type f -size 3M -exec ls -al {} \;
```

## 3&#46; 자바 프로세스 실행해보기

<p id="1542a8d9-541a-44fd-af02-8b5db98ae030"><strong>A&#46; 자바 설치</strong></p>

<span id="beaa6857-387b-4f27-a323-888fe534b0d7"></span>

```bash
$ which java
$ sudo apt update
$ sudo apt install default-jre
$ sudo apt install default-jdk
```

<p id="efab7e1c-d587-402c-b974-398b1e336526"><strong>B&#46; 빌드</strong></p>

<span id="bcf2c872-c20a-4e8b-b0a9-d9213d68ecdc"></span>

```bash
$ git clone [저장소]
$ cd [저장소]
$ ./gradlew clean build

# jar파일을 찾아본다.
$ find ./* -name "*jar"

# 프로세스를 정기 스케줄에 등록하고 관리할 수 있습니다.
# crontab -l : list crontab 
# crontab -e : edit crontab
# vi /etc/crontab : 특정 사용자 권한으로 실행이 가능
```

<p id="f1d4f9e5-d93a-4245-b20e-3f9e54138d0d"><strong>C&#46; 실행</strong></p>

<span id="69376f8b-d35d-47e7-9881-73544421604d"></span>

```bash
$ java -jar [jar파일명] & 
  
# Application을 실행 후 정상적으로 동작하는지 확인해봅니다.
# 브라우저에서도 http://{서버 ip}:{port}로 접근해보세요.
$ curl http://localhost:8080
```

<ul>

<li id="56a64e20-b200-439c-98a7-02f0cfb55319">

<p>-<strong>Dserver&#46;port=8000</strong> 옵션을 활용하여 port를 변경할 수 있어요&#46;</p>

</li>

<li id="6ffb4cda-b904-4750-9d47-ef32e3887908">

<p>서버를 시작 시간이 너무 오래 걸리는 경우 -<strong>Djava&#46;security&#46;egd</strong> 옵션을 적용해보세요&#46;</p>

<span id="6cf82772-a4ef-4b51-b122-246a7add2c68"></span>

```bash
$ java -Djava.security.egd=file:/dev/./urandom -jar [jar파일명] &
```

<ul>

<li id="6af115d5-f893-469a-9a1e-5d05a645a536">

<p><span className="notion-color-blue"><a href="https://lng1982.tistory.com/261">tomcat 구동 시 /dev/random 블로킹 이슈</a></span></p>

</ul>

</li>

<li id="e74ba729-392d-48c9-875a-c2f2c8fc2871">

<p>터미널 세션이 끊어질 경우, background로 돌던 프로세스에 hang-up signal이 발생해 죽는 경우가 있는데요&#46; 이 경우 <span className="notion-color-blue"><a href="https://youngclown.github.io/2018/10/noup"><code><strong>nohup</strong></code></a></span>명령어를 활용합니다&#46;</p>

<span id="33cd38f0-b1f5-4f91-a44c-b448ee7e060b"></span>

```bash
$  nohup java -jar [jar파일명] 1> [로그파일명] 2>&1  &
```

<ul>

<li id="2c3ad5cd-ea72-41b7-8c95-f06dc403b59a">

<p>rxkB/s &#58; Total number of kilobytes received per second</p>

</li>

<li id="ae843199-2835-4633-b6c4-8ac3e7280bb8">

<p>txkB/s &#58; Total number of kilobytes transmitted per second</p>

</li>

<li id="b0954506-d469-425b-ba6a-99c1b498a95d">

<p>active/s &#58; TCP 연결이 CLOSED 상태에서 SYN-SENT 상태로 직접 전환 된 초당 횟수 즉, 서버에서 다른 외부 장비로 TCP 연결한 횟수</p>

</li>

<li id="14886afa-45d8-4cc2-a494-75675579d978">

<p>passive/s &#58; TCP 연결이 초당 LISTEN 상태에서 SYN-RCVD 상태로 직접 전환 한 횟수 즉, 서버에 새롭게 접근한 클라이언트 수</p>

</li>

<li id="5253c98b-afde-4873-9de3-603d3b2fe282">

<p>retrans/s &#58; 초당 재전송 된 총 세그먼트 수</p>
