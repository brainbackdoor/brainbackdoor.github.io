# 본문 애니메이션 도해 작성 가이드

작성일: 2026-10-12 / 글별 검토: 2026-10-13

포스팅과 커리큘럼에 들어가는 그래프·흐름도·비교 도해를 같은 형식으로 제작하기 위한 기준이다. 새로운 에셋을 만들 때 이 문서의 작성 템플릿과 검수 항목을 함께 사용한다.

전체 공개 글 58편의 애니메이션 후보, 이미지 처리 방침, 제작 순서는 [9. 전체 포스팅 작업 목록](#9-전체-포스팅-작업-목록)에 기록했다. 전체 실행 순서와 도해 73개·선택 9개의 제작 목록은 [전체 적용 계획](superpowers/plans/2026-10-13-blog-animated-figures.md)에 기록했다. 현재는 검토와 계획 작성까지만 진행했으며 구현·본문 변경은 하지 않았다.

## 기준과 적용 상태

- 사용자가 지정한 레퍼런스: [kciter.so — 서버 모니터링 분석 가이드](https://kciter.so/posts/server-monitoring-analysis-guide/)
- 분석한 공개 코드: [애니메이션 JavaScript 번들](https://kciter.so/_astro/index.-UPSY4oC.js). 파일명의 해시는 배포에 따라 바뀔 수 있다.
- 현재 기준 예제: B안 목업을 바탕으로 구현한 **정상 전송과 손실 후 재전송 비교 도해**.
- 실제 사이트용 React 컴포넌트와 공통 재생기를 `src/components/figures/`에 구현했다. 한국어·영어 MDX에서 사용할 수 있으며, 아래 경로와 API는 현재 저장소의 구현이다. 배포 완료를 뜻하지는 않는다.
- 타입 검사와 시간 모델·SSR 자동 테스트를 통과했다. 실제 사이트의 브라우저 검수 범위는 문서 끝에 기록하며, 목업에서 확인한 결과와 구분한다.

원본은 Astro의 `client:visible`로 React 컴포넌트를 로드하고, Canvas 2D와 `requestAnimationFrame`으로 도해를 직접 그린다. 트래픽 예제는 3.5초 동안 그래프를 전개하고 완성 상태를 3초 유지한다. 수치·커서·주석이 진행 상황에 맞춰 나타난다.

이 시각 표현과 연출 원칙을 따른다. 각 에셋의 내용과 코드는 직접 작성한다. 모든 자료를 동일한 그래프 모양이나 재생 길이에 맞추지는 않는다. TCP 시퀀스, 요청 큐, 캐시 적중률처럼 주제에 맞는 표현을 선택한다.

## 1. 공통 표현 원칙

1. 도해 하나는 본문의 질문 하나에 답한다. 제목은 무엇을 비교하거나 보여주는지 짧게 적는다.
2. **사건 → 눈에 보이는 변화 → 해석** 순서로 전개한다. 발생하지 않은 사건의 경로나 결과를 처음부터 모두 노출하지 않는다.
3. 선을 그리거나 점을 이동시키는 것은 데이터·시간·상태 변화를 나타낼 때 사용한다. 장식용 움직임을 추가하지 않는다.
4. 비교 패널은 같은 시간축·단위·색의 의미를 공유한다. 같은 시점에서 무엇이 다른지 읽을 수 있어야 한다.
5. 완성 상태를 읽을 시간을 준 뒤 처음으로 돌아간다. 기본 유지 시간은 3초이며 정보량에 따라 늘린다.
6. 설명은 필요한 주석과 짧은 상태 문장으로 제한한다. 큰 소개 문구, 장식용 설명, 불필요한 조작 패널을 붙이지 않는다.
7. 설명을 위해 만든 수치와 시간은 실제 측정값과 구분한다. 의미 있는 캡션 한 줄로 가정을 밝힌다.

## 2. 시각 규격

아래 값은 현재 라이트 디자인의 기준값이다. `src/styles/global.css`의 `--color-figure-*` 공통 토큰을 SVG와 CSS가 공유하며, Canvas는 `readFigureColors()`로 도해 요소의 계산된 CSS 값을 읽는다. 에셋마다 색과 간격을 별도로 하드코딩하지 않는다. Canvas의 기본값은 토큰 누락 시 대체값으로만 사용한다.

| 요소 | 기준 |
| --- | --- |
| 바깥 프레임 | 흰색 `#ffffff`, 테두리 1px `#dee2e6`, 모서리 8px, 그림자 없음 |
| 여백 | 위아래 24px, 내부 20px. 모바일 내부 세로 18px / 가로 16px |
| 플롯 배경 / 격자 | `#f8f9fa` / `#e9ecef`, 격자는 1px |
| 보조선 | `#ced4da`, 생명선·현재 위치는 점선으로 구분 |
| 주요 흐름 | 파랑 `#228be6`, 선 두께 2px |
| 성공·응답 | 초록 `#12b886` |
| 대기·타임아웃 | 주황 `#fd7e14` |
| 손실·오류 | 빨강 `#fa5252`, 색과 함께 ×·텍스트 등으로 의미 표시 |
| 상태 표식 | 작은 점과 짧은 이름, 옅은 배경. 목업은 `#e7f5ff` / `#fff4e6`, 실제 컴포넌트는 파랑·주황 토큰 10%와 프레임 배경을 `color-mix()`로 혼합 |
| 움직이는 점 | 반지름 4px, 흰 윤곽선 1.5px |
| 글꼴 | 사이트 본문 글꼴 상속. 현재 B안은 IBM Plex Sans KR |
| 제목 / 패널 이름 | 13px / 12px. 본문 제목보다 작게 유지 |
| 설명 | 실제 컴포넌트 12px, 줄높이 1.8. 최소 높이 44px로 공간 확보. 캡션은 11px |
| 패널 | 넓을 때 2열, 도해 **컨테이너 내부 폭** 560px 미만에서 1열 |

원본의 Pretendard를 별도 로드하지 않고 블로그 글꼴을 공유한다. 숫자·단위·화살표 라벨은 패널 폭에 맞춰 재배치하며, Canvas 전체를 축소해 글자를 읽기 어렵게 만들지 않는다. 실제 컴포넌트의 Canvas 라벨은 기본 11px, 완료 문구는 12px, 시간 방향 보조 라벨은 10px다. SSR 대체 SVG는 13px 기준 글자를 사용한다. 좁은 폭에서의 최종 가독성은 브라우저로 확인한다.

선·점의 선명한 색과 작은 글자의 색을 분리했다. 텍스트에는 아래 토큰을 사용하고, 밝은 초록·주황 선 색을 작은 글자에 그대로 쓰지 않는다.

| 용도 | CSS 토큰 | 라이트 값 |
| --- | --- | --- |
| 기본 글자 | `--color-figure-text` | `#343a40` |
| 보조 설명 | `--color-figure-muted` | `#586b80` |
| 요청·데이터 라벨 | `--color-figure-blue-text` | `#1765a0` |
| 응답·완료 라벨 | `--color-figure-green-text` | `#087f5b` |
| 대기·타임아웃 라벨 | `--color-figure-orange-text` | `#a54800` |
| 손실·오류 라벨 | `--color-figure-red-text` | `#c92a2a` |

낮은 대비의 목업 보조색 `#868e96`은 실제 컴포넌트에서 사용하지 않는다. 재생 조작 버튼은 추가하지 않는다.

색의 역할은 에셋 안에서 고정한다. 예를 들어 파란 요청이 이동 중이라는 이유만으로 빨간 오류 색으로 변하지 않는다. 다크 모드를 지원하는 지면에 넣을 때에는 배경·선·문자 토큰을 함께 검토한다.

## 3. 시간과 상태 모델

모든 그림과 설명은 하나의 경과 시간 `elapsedMs`에서 계산한다. 프레임마다 임의로 상태를 누적하거나, 그림과 설명에 서로 다른 타이머를 사용하지 않는다.

```ts
// 에셋별 상태 계산과 공통 재생기를 분리하기 위한 개념 예시.
const progress = (time: number, start: number, end: number) =>
  Math.max(0, Math.min(1, (time - start) / (end - start)));

const frame = stateAt(elapsedMs); // 패킷 위치, 숫자, 단계, 설명을 함께 결정
draw(ctx, frame, layout, tokens);
```

- 이벤트마다 시작·도착·완료 시점을 명시한다. 수신 상태는 패킷이 도착한 시점에 바뀐다.
- 이동은 기본적으로 일정한 속도로 진행한다. 완만해지는 움직임이 의미를 전달할 때만 easing을 사용한다.
- 주석은 사건 이후 짧게 나타난다. 현재 TCP 예제의 등장 시간은 약 180~400ms다.
- 이전 사건은 맥락으로 남기고, 현재 사건은 움직이는 점·커서·수치로 구분한다.
- 종료된 타이머에는 “대기 중”을 표시하지 않는다. 과거 대기 구간은 “RTO 만료”처럼 완료된 사건으로 남긴다.
- 루프 경계에서 위치·수치·주석·타이머를 함께 초기화한다. 무작위 데이터가 필요하면 고정 시드를 사용해 같은 사건을 재현할 수 있게 한다.
- 애니메이션 시간은 설명의 속도다. 실제 시간 축을 압축하거나 비선형으로 표현한다면 도해에 그 사실을 밝힌다.

### 기준 예제: TCP 비교 타임라인

SEQ 1000부터 100바이트를 보내고 ACK 1100을 받는다. 손실 예제에는 뒤따르는 데이터가 없어 중복 ACK가 발생하지 않는다. 빠른 재전송을 보여주는 예제는 별도 사건 구성이 필요하다.

| 경과 시간 | 정상 전송 | 손실 후 재전송 |
| --- | --- | --- |
| 0~600ms | 준비 | 준비 |
| 600ms | 데이터 전송 시작 | 데이터 전송 시작, RTO 타이머 시작 |
| 1,050ms | 전송 중 | 첫 데이터 손실, ACK 대기 계속 |
| 1,400ms | 데이터 도착 | 대기 |
| 1,650ms | ACK 1100 전송 시작 | 대기 |
| 2,450ms | ACK 수신, 타이머 정지 | 대기 |
| 3,200ms | 완료 상태 유지 | RTO 만료, 같은 SEQ 재전송, 늘어난 RTO로 타이머 재시작 |
| 4,000ms | 유지 | 재전송 데이터 도착 |
| 4,250ms | 유지 | ACK 1100 전송 시작 |
| 5,050ms | 유지 | ACK 수신, 타이머 정지 |
| 5,050~8,050ms | 완성된 비교 그림 유지 | 완성된 비교 그림 유지 |
| 8,050ms | 처음부터 반복 | 처음부터 반복 |

위 시간은 실제 RTT나 RTO 측정값이 아니다. 두 패널의 시간축을 맞춰 대기와 복구의 차이를 보여주기 위한 연출값이다. 현재 Canvas 높이는 패널당 306px이며, 다른 도해의 공통 고정 높이로 강제하지 않는다.

## 4. 공통 재생 동작

재생 여부는 가시성·문서 숨김·동작 줄이기 설정과 Canvas 준비 상태로 결정한다.

```ts
const shouldRun =
  enabled && inViewport && !document.hidden && !reducedMotion;
```

| 상황 | 동작 |
| --- | --- |
| 처음 화면에 들어옴 | 동작 줄이기 미설정 시 처음부터 자동 재생 |
| 화면 밖 또는 브라우저 탭 숨김 | 시간 누적과 프레임 요청 중단 |
| 다시 보임 | 멈춘 위치에서 이어서 재생 |
| 동작 줄이기 설정 | 움직임 없이 핵심 사건이 드러나는 완성 도해 표시 |
| 동작 줄이기 해제 | 시간을 처음으로 되돌림. 화면에 보이면 재생 |
| 창 크기·배율 변경 | 같은 시점의 그림을 새 크기로 다시 그림 |

홈과 본문의 도해는 별도 조작 버튼 없이 자동 재생한다. 새 에셋에도 일시정지·계속 재생·속도 등의 조작 버튼을 기본으로 추가하지 않는다.

`requestAnimationFrame`의 timestamp 차이로 경과 시간을 계산하고, 정지 시 마지막 timestamp도 비운다. 숨겨진 동안의 시간을 재개 후 한꺼번에 더하지 않는다. 공통 재생기는 250ms 이상의 프레임 간격도 건너뛰어 사건이 갑자기 넘어가는 것을 막는다. 이는 예제의 정지 정책이며, 실제 시간 기반 데이터 재생과 혼용하지 않는다.

## 5. 실제 사이트의 공통 구현 구조

현재 저장소의 Astro + React + MDX 구조를 사용한다. 새 차트 라이브러리를 기본 전제로 추가하지 않고 Canvas 2D로 구현한다. 시안은 목업에서 확인한 뒤 실제 본문에 적용한다.

현재 파일과 책임은 다음과 같다.

```text
src/components/figures/
  AnimatedFigure.tsx       공통 프레임, 제목, 캡션
  useFigurePlayback.ts     시간, 가시성, reduced motion, 정리
  playback.ts              순수 시간 진행·재생 가능 여부 계산
  TcpRecoveryFigure.tsx    TCP 패널 조합, SSR SVG, Canvas 준비·크기·실패 처리
  tcp.ts                   사건 시간표, 순수 상태 계산, 한국어·영어 라벨
  tcpCanvas.ts             Canvas 렌더러, CSS 토큰 읽기, 공통 TCP 좌표
  figures.css              도해 내부 스타일과 컨테이너 반응형 배치
  tcp.test.ts              데이터 도착·ACK·재전송·완료 경계 검증
  playback.test.ts         반복·긴 프레임 간격·재생 조건 검증
  figure-ssr.test.ts        브라우저 없는 렌더링·다중 인스턴스 ID 검증
src/styles/global.css      도해용 공통 토큰
```

### MDX에서 사용하기

`src/content/posts/ko/` 또는 `src/content/posts/en/` 바로 아래에 있는 MDX 파일은 다음과 같이 가져온다. 다른 디렉터리 깊이에서는 상대 경로를 맞춘다.

```mdx
import TcpRecoveryFigure from '../../../components/figures/TcpRecoveryFigure';

<TcpRecoveryFigure client:visible />
```

기본 언어는 한국어다. 영문 글에서는 `<TcpRecoveryFigure lang="en" client:visible />`로 사용한다. CSS는 컴포넌트가 직접 가져오므로 별도 스타일 import가 필요 없다.

홈의 추천 글에는 `variant="preview"`를 사용한다. 같은 시간 모델과 Canvas 렌더러로 손실 후 재전송 패널 하나만 표시하며, 제목·캡션은 접근성 설명으로 유지하고 큰 설명 영역은 생략한다. 기본 본문 변형은 계속 두 패널을 표시한다.

```astro
---
import TcpRecoveryFigure from '../components/figures/TcpRecoveryFigure';
---
<div class="home-diagram">
  <TcpRecoveryFigure variant="preview" client:visible />
</div>
```

위 상대 경로는 `src/pages/index.astro` 기준이다. 글 제목과 “글 읽기” 링크를 별도로 둔다. 홈 플롯은 높이 246px로 시간 좌표만 조정하고 Canvas 라벨의 글자 크기는 유지한다. 자동 재생·화면 밖 정지·동작 줄이기·정적 SVG 대체는 본문과 같은 공통 재생기를 사용한다.

`client:visible`은 최초 React 로드를 지연하는 역할이며, 로드 이후 화면 밖 정지는 공통 재생기의 `IntersectionObserver`가 처리한다. 서버는 완성된 SVG 두 장과 제목·캡션·완료 설명을 먼저 출력한다. Canvas 두 개가 모두 준비되고 실제 너비가 생기면 같은 306px 공간에서 Canvas로 교체한다. JavaScript 비활성화, hydration 전, Canvas 초기화·렌더링 실패 시에는 정적 SVG를 보여준다. reduced motion에서는 완성 시점의 정적 Canvas를 표시한다.

### 다른 에셋에서 공통 재생기 사용하기

`useFigurePlayback()`의 현재 입력과 반환값은 다음과 같다.

```ts
const playback = useFigurePlayback({
  containerRef,          // RefObject<HTMLElement | null>, 도해 전체 프레임
  durationMs,            // 완성 상태 유지까지 포함한 전체 반복 길이
  finalElapsedMs,        // reduced motion에서 보여줄 완성 시점
  enabled: ready,        // 렌더러와 실제 크기가 준비됐는지 여부
  onFrame: renderFrame,  // (elapsedMs: number) => void, 에셋별 상태 계산과 그리기
});
// playback.reducedMotion / running: 현재 상태
// playback.redraw(): 시간을 바꾸지 않고 현재 장면 다시 그리기
```

`onFrame`은 매 프레임 호출되므로 Canvas를 그리되, React 상태는 사건 단계가 바뀔 때만 갱신한다. 크기·DPR·폰트가 바뀌면 에셋이 `redraw()`를 호출한다. 공통 재생기는 Canvas·TCP 사건을 알지 않으며, Canvas 준비와 실패 판단은 에셋 컴포넌트가 맡는다.

`AnimatedFigure`에는 `containerRef`, `title`, `caption`, `children`과 아래 재생 속성을 전달한다. 언어에 따른 제목·캡션은 에셋에서 준비한다.

```tsx
<AnimatedFigure
  containerRef={containerRef}
  title={title}
  caption={caption}
  running={playback.running}
>
  {/* 에셋별 정적 대체 도해, Canvas, 짧은 설명 */}
</AnimatedFigure>
```

새 에셋은 프레임과 재생기를 재사용하고, 사건표·상태 함수·렌더러·정적 대체만 추가한다. TCP 전용 높이·좌표·설명을 다른 주제에 강제로 적용하지 않는다.

현재 구현과 앞으로 추가할 에셋은 다음 원칙을 따른다.

- **인스턴스 격리:** 전역 `document.querySelector` 대신 컴포넌트 ref와 고유 ID를 사용한다. 한 글에 도해가 여러 개 있어도 각각 재생·정지할 수 있어야 한다.
- **프레임과 콘텐츠 분리:** 공통 재생기는 TCP·큐·캐시를 알 필요가 없다. 에셋은 시간에 따른 상태 계산과 그리기를 담당한다.
- **React 상태 사용:** Canvas의 프레임 시간은 ref로 관리하고, 제목·설명 등 DOM 상태는 실제 단계가 바뀔 때 갱신한다. 매 프레임 React 전체를 다시 렌더링하지 않는다.
- **정리:** unmount 시 RAF 취소, observer 해제, 이벤트·미디어 쿼리 리스너 제거를 수행한다. 재진입 시 중복 루프가 생기지 않게 한다.
- **크기와 선명도:** `ResizeObserver`로 실제 컨테이너 크기를 관찰한다. CSS 크기와 DPR을 구분하고, 배킹 크기는 `CSS 크기 × DPR`로 설정한다. 크기·배율이 변할 때만 버퍼를 재설정한다. 초기 너비가 0이면 그리기를 미루고, 실제 너비가 생기면 같은 시점을 다시 그린다.
- **좌표와 글꼴:** Canvas에는 CSS 픽셀 좌표를 사용한다. 매번 `setTransform`으로 DPR을 적용해 스케일이 누적되지 않게 한다. 웹 폰트 로드 후 같은 시점을 다시 그린다.
- **SSR·로딩:** 렌더 단계에서 `window`나 Canvas context를 요구하지 않는다. 제목·대체 설명과 공간을 서버에서 출력해 hydration 전에도 의미가 남고 지면이 튀지 않게 한다.
- **정적 대체:** JavaScript나 Canvas를 사용할 수 없으면 읽을 수 있는 설명 또는 정적 도해를 제공한다. 움직임을 줄인 상태에서도 원인과 결과를 이해할 수 있어야 한다.
- **초기화 실패:** Canvas context를 얻지 못하거나 렌더링을 계속할 수 없으면 RAF를 중단하고 대체 내용을 표시한다. 빈 화면을 반복해서 그리지 않는다.

원래 목업은 단일 도해용 IIFE다. 실제 사이트에서는 이를 그대로 복사하지 않고 위의 React 컴포넌트와 공통 재생기를 사용한다. 각 인스턴스는 ref와 `useId()`를 가지며, observer·RAF·가시성·미디어 쿼리·폰트 리스너를 해제한다. SSR에서는 비활성 Canvas를 접근성 트리에서 숨기고, Canvas 준비 후에는 대체 SVG를 숨겨 동일 설명이 중복되지 않게 한다.

## 6. 접근성과 콘텐츠

- Canvas에 `role="img"`와 의미 있는 이름·설명을 제공한다. “애니메이션”이라고만 쓰지 않고 주요 사건과 결론을 설명한다.
- 접근성 트리에 같은 설명이 중복되지 않게 연결한다. 매 프레임 변하는 수치를 `aria-live`로 읽게 하지 않는다.
- 조작 버튼을 제거해도 도해 제목·캡션·정적 대체의 접근성 설명을 유지한다. OS의 동작 줄이기 설정에서는 완성된 정적 장면을 제공한다.
- 색만으로 정상·오류를 구별하지 않는다. 텍스트·표식·선 형태를 함께 사용한다.
- 정상 동작과 reduced motion 모두 본문에서 필요한 정보를 전달한다. 마지막 장면만으로 설명이 안 되면 정적인 여러 장면을 제공한다.
- 캡션은 단위·시간 방향·데이터 출처·연출 가정 중 필요한 내용만 담는다. 구현 기술명과 제작 설명은 독자용 지면에 넣지 않는다.

‘제작 권장’은 움직임으로 과정·인과관계·비교를 더 잘 설명할 수 있는 글이다. ‘선택 후보’는 정적인 재작성만으로도 충분할 수 있어 첫 시안 이후 결정할 글이다. ‘유지’도 검토한 결과이며 누락된 글이 아니다. 글 하나에 여러 후보가 있고 여러 글이 같은 도해를 공유하므로 글 수를 새 컴포넌트 수로 사용하지 않는다.

### 이미지 대체 방침

1. **개념 도표·흐름도·비교 그래프는 애니메이션 대체를 우선한다.** 원래 설명하던 노드·관계·단위·라벨·분기·조건을 먼저 목록화하고, 새 도해에 같은 정보가 담긴 뒤 본문의 해당 이미지를 교체한다. 개념 설명을 이미지 확대·페이드인으로만 처리하지 않는다.
2. **실제 결과를 보여주는 캡처는 근거를 보존한다.** Wireshark·Arthas·EXPLAIN·Grafana 등의 캡처는 실제 행·수치와 맞춘 강조 재생 또는 읽을 수 있는 표/그래프로 재작성할 수 있다. 개념 모형이 캡처의 측정값을 대신하는 경우에는 원본도 근거로 접근 가능하게 남긴다. 캡처만으로 시계열 원자료를 얻을 수 없으면 새 측정 곡선을 추정해 넣지 않는다.
3. **설정 화면은 동작 설명과 역할이 다르다.** AWS·IDE 메뉴와 입력 위치를 알려주는 캡처는 유지하고, 앞뒤 문단의 요청 이동·자원 생성·트레이스 수집 과정을 애니메이션으로 추가한다. 실습에 필요한 설정 위치가 새 도해에도 담기는 경우만 캡처를 완전히 대체한다.
4. **기록 사진·직접 그린 작품·영상은 원본 사용을 권장한다.** 재현할 시스템 동작이 없는 가족·행사·여행 사진은 원본의 기록성이 중요하다. 사진을 흔들거나 얼굴·작품을 임의로 움직이는 것을 도해 대체로 계산하지 않는다. 책 표지·외부 서비스 로고·북마크 썸네일도 제작 대상에서 제외한다.
5. **구분선은 별도 정리 후보다.** 89곳의 래스터 구분선은 향후 CSS 구분선으로 바꿀 수 있으나 이번 애니메이션 제작량에 넣지 않는다. 현재 파일은 변경하지 않았다.
6. 원본 파일과 출처는 저장소에 보존한다. 기존 이미지 앵커로 접근하는 주소도 이어지게 한다. 대체 도해는 동작 줄이기·JavaScript 미사용 시에도 원래 정보를 읽을 수 있어야 한다.

### 우선순위와 작업 크기

- **P1:** 과정이 명확하고 이해 효과·재사용성이 커서 첫 제작 묶음에 적합하다.
- **P2:** P1의 표현 방식을 재사용하거나 여러 조건을 검증한 뒤 제작한다.
- **P3:** 개념 정확성·콘텐츠 보존을 먼저 정리하거나, 정적 재작성과 비교해 결정한다.
- **선택:** 본문에 필수적인 움직임은 아니며 우선 묶음의 시안을 본 뒤 결정한다.
- 작업 크기 **S / M / L**은 단일 흐름 / 비교·분기 / 여러 독립 장면을 뜻한다. 일정·견적은 아니며, 사실 검증과 원자료 확보량에 따라 달라진다.

### 사실 확인 근거

- N01: 버퍼 용량과 AQM을 구분하고 고정 FIFO burst의 가정을 표시한다. [RFC 7567 §2.3](https://www.rfc-editor.org/rfc/rfc7567.html#section-2.3).
- N03: 윈도 0에서도 probe와 현재 윈도 ACK를 사용하며, 열린 윈도가 송신 측에 전달되어야 재개를 표현한다. [RFC 9293 §3.8.6.1](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.8.6.1).
- W03: 저장된 응답의 재사용 조건과 freshness를 구분한다. 예제는 완전한 200 응답과 유효 기간 내 같은 키로 제한한다. [RFC 9111 §3–4](https://www.rfc-editor.org/rfc/rfc9111.html#section-3).
- T01: monitor 락을 얻기 위해 막힌 상태는 BLOCKED다. 실제 소유 관계는 원문 dump를 우선한다. [JDK Thread.State](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.State.html#BLOCKED).
- D03: 복합 인덱스의 선두 열 범위를 사용한다. 도해가 전체 옵티마이저 동작을 대신하지 않는다. [MySQL 다중 열 인덱스](https://dev.mysql.com/doc/refman/8.4/en/multiple-column-indexes.html).
- S03: RDD transformation은 action이 결과를 요구할 때 계산한다. [Spark RDD Programming Guide](https://spark.apache.org/docs/latest/rdd-programming-guide.html#rdd-operations).
