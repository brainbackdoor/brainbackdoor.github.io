## <strong>🪜 Commit Message</strong>

<p id="e4dd0a07-4cb1-4be6-a4ba-7ecea7e0f70e">기본적으로 <span className="notion-color-blue"><strong><a href="https://docs.google.com/document/d/1QrDFcIiPjSLDn3EL15IJygNPiHORgU1_OOAqWjiDU5Y/edit">Angular JS Git Commit Message Conventions</a></strong></span>를 따른다&#46;</p>

<p id="79d2fab1-1cde-480d-a5ce-6fca0817d052">상세 메세지 내용은 한국어를 사용한다&#46;</p>

<ul>

<li id="436ff7b1-c83a-4f3d-b56c-4b0424537405">

<p><code>feat</code>&#58; 새로운 기능</p>

</li>

<li id="5da9a172-74a7-4f43-bf8d-d79a8a964f7d">

<p><code>fix</code>&#58; 버그를 수정</p>

</li>

<li id="ad453587-2488-49d5-b825-409e112a8fd6">

<p><code>refactor</code>&#58; 이미 있는 코드에 대한 리팩토링</p>

</li>

<li id="69e7f398-5b2b-419d-ba3b-7cfc02a3d3ac">

<p><code>style</code>&#58; 코드 포매팅에 관한 스타일 변경</p>

</li>

<li id="859f56d2-fdca-4127-a842-091b3d106edd">

<p><code>docs</code>&#58; Document 변경 사항</p>

</li>

<li id="72e95165-d7b2-4bcc-99cc-582bac799b37">

<p><code>test</code>&#58; Test Code에 대한 commit</p>

</li>

<li id="d8aef432-a6c9-4308-8a2a-9b60f0e4b8f8">

<p><code>chore</code>&#58; 그 외의 작은 수정들</p>

</li>

</ul>

## <strong>🖥️ Coding Convention</strong>

<span id="84ef3fc1-a95a-4cb4-9abc-d2477af803b7"></span>

#### Test code Convention

<p id="9178ac06-ae33-4a96-a4cd-49c96ea28351"><a href="/posts/9178ac06-ae33-4a96-a4cd-49c96ea28351">테스트 작성 기준</a></p>

<ul>

<li id="6d4c892e-a1c1-4c3d-b0ec-5cc9aed0e2da">

<p>F&#46;I&#46;R&#46;S&#46;T 원칙을 지킨다&#46;</p>

</li>

<li id="f4f0d4a8-495b-4b2b-828a-22df527a0483">

<p>단위테스트, 인수테스트, 문서화를 위한 테스트는 필수로 작성한다&#46;</p>

</li>

<li id="da3fa2a7-8fc1-4a09-a053-8fafb3c64f12">

<p>인수테스트는 Given, When, Then 패턴을 따른다&#46;</p>

</li>

<li id="bddfe9f5-6989-43c4-882b-ca12f81e109b">

<p>인수테스트 작성시 공통된 로직은 xxSteps&#46;kt 파일에 모아둔다&#46;</p>

</li>

<li id="78f05d51-465d-47e6-90ef-1b8a9e6e4819">

<p>가급적 Mock 보단 Fake 객체를 활용한다&#46;</p>

</li>

</ul>

#### Kotlin code Convention

<p id="305fe545-4b2b-4237-bd48-7454bbb2915b">bad</p>

<span id="e02c2fda-7a2a-4fca-88a3-aa98c2b8d2fb"></span>

```kotlin
fun thisIsFunction(a: Int,
                   b: Long,
                   c: String): String {
    return ""
}

fun thisIsFunction(
        a: Int,
        b: Long,
        c: String): String {
    return ""
}

```

<p id="de3c4f3f-a83d-4ceb-943c-05f91ecc8650">good</p>

<span id="3c54104c-5ac7-4add-9e5c-de816fbd6028"></span>

```kotlin
fun thisIsFunction(
        a: Int,
        b: Long,
        c: String
): String {
    return ""
}
```

<blockquote id="d79df720-cf79-4ebf-a443-2c3481724f27">

<p>parameter is in a separate line with indentation&#46; Also, the closing parenthesis should be on a new line&#46;</p>

</blockquote>

<p id="63032031-7fe9-408d-b1af-116417a8343f"><span className="notion-color-blue"><a href="https://kotlinlang.org/docs/reference/coding-conventions.html#function-formatting">https&#58;//kotlinlang&#46;org/docs/reference/coding-conventions&#46;html&#35;function-formatting</a></span></p>

<ul>

<li id="023ee016-e101-4f9b-bc29-85cec41d556e">

<p>매개 변수가 많은 경우 별도의 줄에서 들여쓰기를 한다&#46; 또한 닫는 괄호도 새로운 줄에 있어야 한다&#46;</p>

</li>

<li id="1257e55b-e9e4-4738-953a-788afc908221">

<p>파라미터가 2개인 경우 파라미터의 개수를 기준으로 개행하는 것이 아니라, margin(120)을 기준으로 개행한다&#46;</p>

</li>

</ul>

<p id="0c46ea70-c494-4fc3-9994-a4b8f8785853">bad</p>

<span id="fb2134a9-ce8d-4e11-b723-b18accd6332d"></span>

```kotlin
fun thisIsFunction() = ""

fun thisIsFunction(): Unit {
}
```

<p id="9e92bd9f-9081-46f6-a40a-75c4ff520562">good</p>

<span id="b2c2646a-aded-428a-b404-14e0f3b1aeb8"></span>

```kotlin
fun thisIsFunction(): String {
    return ""
}

fun thisIsFunction() {
}
```

<ul>

<li id="07881d54-3f34-4d45-b004-b08ceb25f783">

<p>함수와 메서드의 반환 타입은 명시한다&#46; 단, <code>Unit</code>은 예외이다&#46;</p>

<ul>

<li id="050b99bc-7055-4925-bd77-73dfdc680a61">

<p><span className="notion-color-blue"><a href="https://kotlinlang.org/docs/reference/coding-conventions.html#unit">https&#58;//kotlinlang&#46;org/docs/reference/coding-conventions&#46;html&#35;unit</a></span></p>

</li>

</ul>

</li>

</ul>

<blockquote id="6985230f-8329-419e-8e4c-a8d582ac166c">

<p>Always explicitly specify function return types and property types (to avoid accidentally changing the return type when the implementation changes)</p>

</blockquote>

<p id="e415feb5-f24b-402b-a6bf-74b7b533dfa5"><span className="notion-color-blue"><a href="https://kotlinlang.org/docs/reference/coding-conventions.html#coding-conventions-for-libraries">https&#58;//kotlinlang&#46;org/docs/reference/coding-conventions&#46;html&#35;coding-conventions-for-libraries</a></span></p>
