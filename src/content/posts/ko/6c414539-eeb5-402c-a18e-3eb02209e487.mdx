<p id="a65567b9-b0b2-4236-a06c-f2699b0d72b0">기존의 가상화 기술은 <strong>하이퍼바이저</strong>를 이용해 여러 개의 운영체제를 하나의 호스트에서 생성해 사용하는 방식입니다&#46; 하이퍼바이저는 호스트 컴퓨터에서 다수의 운영체제를 동시에 실행하기 위한 논리적 플랫폼 정도로 이해해도 충분하다고 생각합니다&#46;</p>

<p id="cfb789fc-63ca-4974-a307-97e8ab9fc2d9">중요한 점은, <u>각 종 시스템 자원을 가상화하고 독립된 공간을 생성하는 작업은 반드시 하이퍼바이저를 거치기 때문에 일반 Host에 비해 성능의 손실이 발생한다는 것</u>입니다&#46;</p>

<p id="3a9ec2cb-bff6-4c0c-ba25-f210f79ef17a">뿐만 아니라, 가상머신은 GuestOS를 사용하기 위한 라이브러리, 커널 등을 전부 포함하기에 가상 머신을 배포하기 위한 이미지로 만들었을 때 <strong>이미지 크기가 커져 </strong>가상머신 이미지를 애플리케이션으로 배포하기는 부담스럽습니다&#46; (기존의 가상화는 <span className="notion-color-blue"><strong><a href="https://m.blog.naver.com/PostView.nhn?blogId=complusblog&amp;logNo=220990379931">전가상화, 반가상화</a></strong></span> 등의 방식으로 분류됩니다&#46;)</p>

<p id="3c241487-4cf7-4e60-af85-f72cf05a01e0">우리가 원하는건 특정 환경에 종속되지 않은 상태로 어플리케이션을 띄우는 것입니다&#46;</p>

<p id="d11684d6-f8c4-433e-a25d-9ab7aaa20f71">단순히 <span className="notion-color-orange_background"><strong>어플리케이션만을 띄우고 싶을 뿐인데 OS까지 띄우는것은 엄청난 낭비</strong></span>입니다&#46;</p>

<blockquote id="684f25ac-8484-429f-a478-106dc2727282">

<p>"격리된 CPU, 메모리, 디스크, 네트워크를 가진 공간을 만들고 이 공간에서 프로세스를 실행해서 유저에게 서비스" 하려면 어떻게 해야 할까?</p>

</blockquote>

<ul>

<li id="eadcbcf4-a3c9-4ed9-b186-d565d6eade0f">

<p id="47af5ae3-7a5c-4ec1-b15a-e935f8b820fe">컨테이너에 필요한 커널은 호스트의 커널을 공유해 사용하고 컨테이너 안에는 애플리케이션을 구동하는데 필요한 라이브러리 및 실행 파일만 존재하기 때문에 컨테이너를 이미지로 만들었을 때 이미지의 용량 또한 가상 머신에 비해 대폭 줄어듭니다&#46;</p>

<p id="c9230359-dbe4-4660-b2cb-8528eee3b0e3">무엇보다 컨테이너의 내용을 수정해도 호스트 OS에 영향을 끼치지 않습니다&#46; 단, 이는 컨테이너 쓰기 계층 안의 변경일 때이며 bind mount로 연결한 호스트 경로나 volume을 수정하면 그 내용은 컨테이너를 지워도 남습니다&#46;</p>

<p id="72c3f26f-3985-46ed-a079-b5c2cd9bb268">이에 <span className="notion-color-orange_background"><strong>애플리케이션의 개발과 배포가 편해지며, 여러 애플리케이션의 독립성과 확장성이 높아집니다&#46;</strong></span></p>

## 1&#46; 도커 컨테이너 설치

<span id="3f3d6780-88ad-4757-ae87-ca2c233c9b2f"></span>

```bash
$ sudo apt-get update && \
sudo apt-get install -y apt-transport-https ca-certificates curl software-properties-common && \
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo apt-key add - && \
sudo apt-key fingerprint 0EBFCD88 && \
sudo add-apt-repository "deb [arch=amd64] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" && \
sudo apt-get update && \
sudo apt-get install -y docker-ce && \
sudo usermod -aG docker ubuntu && \
sudo curl -L "https://github.com/docker/compose/releases/download/1.23.2/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose && \
sudo chmod +x /usr/local/bin/docker-compose && \
sudo ln -s /usr/local/bin/docker-compose /usr/bin/docker-compose
```

<p>컨테이너 실행환경을 이해하면 옵션을 사용하기 수월합니다&#46;<br />가령, <code><strong>i 옵션</strong></code>은 표준 입력을 받도록 설정하는 것으로 파이프라이닝이나 키보드 입력 등이 이에 해당되며, <code><strong>t 옵션</strong></code>은 가상 터미널 설정입니다&#46;<br />따라서, -i와 -t가 조합되면, <strong>가상 터미널로 표준 입력을 입력</strong>할 수 있으며, -t 하나만 쓰여서는 아무런 의미가 없습니다&#46; (터미널은 있는데 입력은 안되는 상황이므로)<br />반면, -i는 홀로 쓰여도 의미가 있습니다&#46; 파이프라이닝 등으로 터미널 없이 입력하는 기능이 존재하기 때문입니다&#46;<br />한편, <code><strong>d 옵션</strong></code>은 -i, -t와 함께 쓰일 수 없습니다&#46; background에서 돌아가기 때문에, -i로 입력을 대기할수도, -t로 가상 터미널을 제공할수도 없기 때문입니다&#46;</p>

</li>

</ul>

<p id="d41286fc-0cbc-4e02-9ffb-5a1c7026e0bc">⁉️ 도커 데몬은 크게, 컨테이너 이미지 빌드, 관리, 공유, 실행 및 컨테이너 인스턴스 관리 등의 기능을 하며, 앞에서 살펴봤듯 모든 컨테이너를 자식 프로세스로 소유합니다&#46; 이에 따른 문제점은 없을까요?</p>

<blockquote id="d31e40d2-5b37-4de9-8c79-d99de488401c">

<p><strong><span className="notion-color-blue"><a href="https://www.samsungsds.com/kr/insights/docker.html">흔들리는 도커(Docker)의 위상&#58; OCI와 CRI 중심으로 재편되는 컨테이너 생태계</a></span></strong></p>

</blockquote>

## 5&#46; Docker Network

<span id="9e07c178-bdcc-41bb-81e9-84feb6d31bb3"></span>

### 들어가기에 앞서

<span id="7024307b-2349-49b2-85aa-6e103014f626"></span>

#### a&#46; veth interface

<p id="521e7d57-fba1-49ce-b3b9-816ce376af3a">랜카드에 연결된 실제 네트워크 인터페이스가 아닌, 가상으로 생성한 네트워크 인터페이스입니다&#46;</p>

<p id="580d9433-0d5e-4a95-935e-659296e82b54">일반적인 네트워크 인터페이스와는 달리 패킷을 전달받으면, 자신에게 연결된 다른 네트워크 인터페이스로 패킷을 보내주기 때문에 항상 쌍(pair)으로 생성해야 합니다&#46;</p>

<span id="aa210d1c-bb59-418d-bfea-6680a2df42cd"></span>

#### b&#46; NET namespace

<p id="06a75703-13a9-4608-9525-9b28fa4c2792">리눅스 격리 기술인 namespace 중 네트워크와 관련된 부분을 말합니다&#46;</p>

<p id="288bc3ec-2e8c-4e08-a6db-79a3ae78a865">네트워크 인터페이스를 각각 다른 namespace에 할당함으로써 서로가 서로를 모르게끔 설정할 수 있습니다&#46;</p>

## 6&#46; Docker Volume

<p id="e5d47f6c-6166-49d8-9fa4-b93f2ea1f502">도커 이미지로 컨테이너를 생성하면 이미지는 <span className="notion-color-orange_background"><strong>읽기 전용</strong></span>이 되며, 컨테이너의 변경 사항만 별도로 저장해서 각 컨테이너의 정보를 보존한다고 앞에서 설명한 바 있습니다&#46;</p>

<p id="a1826478-ba85-428b-8c72-6d6e8df45599">하지만 mysql과 같이 컨테이너 계층에 저장돼 있던 데이터베이스의 정보를 삭제해서는 안되는 경우도 있습니다&#46; 컨테이너 데이터를 영속적인 데이터로 활용하기 위한 방법 중 볼륨을 활용하는 방안이 있습니다&#46;</p>

<LessonFigure figureId="C06" sourceBlockId="a1826478-ba85-428b-8c72-6d6e8df45599" client:visible />

<p id="731eb847-fa6b-427b-8d2d-c187ffe03a11"><code>-</code><code><strong>v 옵션</strong></code>은 호스트의 디렉터리를 컨테이너의 디렉터리에 마운트합니다&#46; 따라서 컨테이너의 해당 경로에 파일이 있었다면 호스트 디렉터리에 가려져 보이지 않습니다&#46; 이미지 안의 파일이 지워지는 것은 아니며, 비어 있는 볼륨을 처음 연결할 때는 기본적으로 반대로 컨테이너의 기존 파일이 볼륨으로 복사됩니다(volume-nocopy로 끌 수 있습니다)&#46;</p>

<span id="6d842aaf-9c89-4447-b2c9-269e8a55586f"></span>

```bash
$ docker run -d \
--name wordpressdb_hostvolume \
-e MYSQL_ROOT_PASSWORD=password \
-e MYSQL_DATABAS=wordpress \
-v /home/wordpress_db:/var/lib/mysql \
mysql:5.7

$ docker run -d \
--name wordpress_hostvolume \
-e MYSQL_ROOT_PASSWORD=password \
--link wordpressdb_hostvolume:mysql \
-p 80 \
wordpress

$ ls /home/wordpress_db
$ docker stop wordpressdb_hostvolume wordpress_hostvolume
$ docker rm wordpressdb_hostvolume wordpress_hostvolume
```

<p id="96edc25e-5e05-4605-b65a-9db74503ea9b">이처럼 컨테이너가 아닌 외부에 데이터를 저장하고 컨테이너는 그 데이터로 동작하도록 설계(stateless)하여야 합니다&#46; <span className="notion-color-orange_background"><strong>컨테이너 자체는 상태가 없고 상태를 결정하는 데이터는 외부로부터 제공받도록 구성</strong></span>하도록 합니다&#46;</p>
