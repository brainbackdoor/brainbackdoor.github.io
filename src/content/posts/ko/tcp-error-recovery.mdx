## 재전송의 두 가지 트리거

TCP는 손실을 두 가지 방식으로 감지합니다. 하나는 타임아웃(RTO), 다른 하나는 중복 ACK를 통한 빠른 재전송(Fast Retransmit)입니다. 전자는 보수적이고 느리며, 후자는 공격적이고 빠릅니다.

> 세 개의 중복 ACK를 받으면, TCP는 타임아웃을 기다리지 않고 손실로 추정한 세그먼트를 재전송합니다. ([RFC 5681, 3.2절](https://www.rfc-editor.org/rfc/rfc5681#section-3.2))

## RTO는 어떻게 계산되나

RTO는 고정값이 아니라 관측된 왕복 시간(RTT)을 기반으로 끊임없이 추정됩니다.

```js
// 첫 RTT 측정 이후, 새 표본 R을 얻었을 때의 의사 코드
alpha = 1 / 8
beta  = 1 / 4

// 갱신 전 SRTT로 편차를 먼저 계산
RTTVAR = (1 - beta) * RTTVAR + beta * abs(SRTT - R)
SRTT   = (1 - alpha) * SRTT + alpha * R
RTO    = SRTT + max(G, 4 * RTTVAR) // G: 시계 정밀도
RTO    = max(RTO, 1 second)        // RFC 6298의 권고 하한
```

`RTTVAR`는 갱신 전의 `SRTT`로 계산합니다. 타이머가 만료되면 아직 확인받지 못한 데이터를 재전송하고 RTO를 두 배로 늘려 타이머를 다시 시작합니다. 계산과 타이머 동작은 [RFC 6298](https://www.rfc-editor.org/rfc/rfc6298)에 정의되어 있습니다.

## 실전에서 확인하기

실제 트래픽에서 재전송을 관찰하려면 `tcpdump`로 캡처한 뒤 흐름을 따라가면 됩니다.

```bash
# eth0 인터페이스에서 특정 호스트의 TCP 트래픽을 파일로 저장
tcpdump -i eth0 -nn -w tcp-flow.pcap 'tcp and host 10.0.1.42'
```

캡처 파일에서 같은 연결의 시퀀스 번호와 ACK를 따라가며 재전송을 확인합니다. PSH 플래그만으로 재전송을 구분할 수는 없습니다. 재전송 비율은 평소 기준선, RTT, 패킷 손실, 수신 윈도 크기와 함께 살펴봐야 합니다.

## 정리

TCP의 신뢰성은 마법이 아니라 관측·추정·재전송의 반복입니다.
