## 3&#46; MySQL 서버 성능 개선대상 식별하기

<span id="d4bc0a68-90e3-4ae6-9e82-7359e27fbc67"></span>

```sql
## 프로세스 목록
SHOW PROCESSLIST;

## 슬로우 쿼리 확인
SELECT query, exec_count, sys.format_time(avg_latency) AS "avg latency", rows_sent_avg, rows_examined_avg, last_seen
FROM sys.x$statement_analysis
ORDER BY avg_latency DESC;

## 성능 개선 대상 식별
SELECT DIGEST_TEXT AS query,
             IF(SUM_NO_GOOD_INDEX_USED > 0 OR SUM_NO_INDEX_USED > 0, '*', '') AS full_scan,
             COUNT_STAR AS exec_count,
             SUM_ERRORS AS err_count,
             SUM_WARNINGS AS warn_count,
             SEC_TO_TIME(SUM_TIMER_WAIT/1000000000000) AS exec_time_total, 
             SEC_TO_TIME(MAX_TIMER_WAIT/1000000000000) AS exec_time_max, 
             SEC_TO_TIME(AVG_TIMER_WAIT/1000000000000) AS exec_time_avg_ms, SUM_ROWS_SENT AS rows_sent,
             ROUND(SUM_ROWS_SENT / COUNT_STAR) AS rows_sent_avg, SUM_ROWS_EXAMINED AS rows_scanned,
             DIGEST AS digest
   FROM performance_schema.events_statements_summary_by_digest ORDER BY SUM_TIMER_WAIT DESC

##  I/O 요청이 많은 테이블 목록
SELECT * FROM sys.io_global_by_file_by_bytes WHERE file LIKE '%ibd';

## 테이블별 작업량 통계 
SELECT table_schema, table_name, rows_fetched, rows_inserted, rows_updated, rows_deleted, io_read, io_write
FROM sys.schema_table_statistics
WHERE table_schema NOT IN ('mysql', 'performance_schema', 'sys');


## 총 메모리 사용량 확인
SELECT * FROM sys.memory_global_total;

## 스레드별 메모리 사용량 확인
SELECT thread_id, user, current_allocated 
FROM sys.memory_by_thread_by_current_bytes
LIMIT 10;

## 최근 실행된 쿼리 이력 기능 활성화
UPDATE performance_schema.setup_consumers SET ENABLED = 'yes' WHERE NAME = 'events_statements_history'
UPDATE performance_schema.setup_consumers SET ENABLED = 'yes' WHERE NAME = 'events_statements_history_long'

## 최근 실행된 쿼리 이력 확인
SELECT * FROM performance_schema.events_statements_history
```

<ul>

<li id="12162506-8c69-47c6-8c44-66d9ecf26220">

<p>thread&#95;cache&#95;size는 지나치게 높여둘 필요는 없으며 일반적으로 threads&#95;connected의 피크 치보다 약간 낮은 수치 정도를 설정하는 것이 좋습니다&#46; 이를 통해 쓰레드가 생성되고 소멸되면서 겪게 되는 메모리, 각종 자원, 시간 등의 낭비를 줄일 수 있습니다&#46;</p>

</li>

</ul>

### B&#46; 커넥션 튜닝

<span id="9770f611-6a26-42c3-8f52-c3ea955a6c25"></span>

```sql
mysql> SHOW VARIABLES LIKE '%max_connection%';
mysql> SHOW STATUS LIKE '%CONNECT%';
mysql> SHOW STATUS LIKE '%CLIENT%';
```

<ul>

<li id="7db044ad-31e4-4307-beab-f90af8f07e95">

<p>connect&#95;timeoutMySQL이 클라이언트로부터 접속 요청을 받는 경우 몇 초까지 기다릴지를 설정하는 변수로, 기본 값은 5초이며 일반적으로 수정할 필요는 없습니다&#46;</p>

</li>

<li id="46f415cc-2b67-4645-952f-7c5f0daa1fae">

<p>Interactive&#95;timeout‘mysql&gt;’과 같은 콘솔이나 터미널 상에서의 클라이언트 접속을 의미하며, 기본 값으로 8시간이 잡혀 있으나 1시간 정도로 낮추는 것이 좋습니다&#46;</p>

</li>

<li id="fd563e0d-8332-4fa7-8406-0c753abe5377">

<p>wait&#95;timeout접속한 후 쿼리가 들어올 때까지 기다리는 시간으로, 접속이 많은 DBMS에서는 이 값을 낮춰 sleep 상태의 Connection들을 정리하여 전체 성능을 향상시킬 수 있습니다&#46; 하지만 값을 너무 낮추게 되면 지나치게 잦은 커넥션이 발생할 수 있으므로, 보통 15&#126;20 사이의 값을 설정합니다&#46; Aborted client는 2% 아래인 것이 바람직한 상태입니다&#46;</p>

</li>

<li id="699e88a1-35fe-4c67-904f-589bb2f2dd1e">

<p>max&#95;connections서버가 허용하는 최대한의 커넥션 수입니다&#46; 서버의 사양에 따라 달라질 수 있으며 일반적으로 120&#126;250개 정도로 설정합니다&#46; 하지만 접속이 많고 고용량 서버의 경우 1000개 정도의 높은 값을 설정하는 것도 가능하니, Too many connection 에러가 발생하지 않도록 적절한 값을 설정하는 것이 중요합니다&#46;</p>

</li>

<li id="1ed777fa-3fa4-4d0a-a51a-0a524f6e8502">

<p>back&#95;logmax&#95;connection 설정값 이상의 접속이 발생할 때 얼마만큼의 커넥션을 큐에 보관할지에 대한 설정 값으로, 기본 값은 50이며 접속이 많은 서버의 경우 이 값을 늘릴 필요가 있습니다&#46;</p>

</li>

</ul>
