## 1&#46; Thread dump

<p id="e39be2d1-bf2e-47e7-9aee-e4315653bcf3">Thread dump를 통해 Thread가 무슨 일을 하는지 알 수 있어요&#46; </p>

<span id="5571a7d3-c32d-4b10-b39d-03096d73e895"></span>

#### A&#46; Thread 덤프 생성

<span id="922a22a7-6090-4553-8bfa-2289f33f60f5"></span>

```bash
$ ps -ef | pgrep java
$ jstack [pid] > thread.dump
```

<span id="f031fa4c-9937-4583-85a3-8d303d88ea74"></span>

<p>Thread 이름, 식별자, 우선순위(prio), Thread가 점유하는 메모리 주소를 의미하는 Thread ID(tid), OS에서 관리하는 Thread ID (nid), Thread 상태 (NEW | RUNNABLE | BLOCKED | WAITING | TIMED&#95;WAITING | TERMINATED) 등의 정보를 확인할 수 있어요&#46;</p>

<p id="d1113fe3-8c35-4a44-b6c6-ab6dcc78201d">b&#46; <strong>Thread dump 로컬로 download</strong></p>

<span id="d1dfe239-47cb-4385-9617-cb73e7fa98df"></span>

```bash
# 운영서버에서 Bastion으로 파일 옮기기
$ rsync -avzh [원격대상경로] [받을경로]
# 예)
$ rsync -avzh ubuntu@2.2.2.2:/home/ubuntu/log/ ./log/

# Bastion 서버에서 파일 다운로드
$ scp -i [pem키] ubuntu@1.1.1.1:/home/ubuntu/log/thread.dump .
```

```bash

$ thread -b
```

<ul>

<li id="5f9f76e3-7af5-4990-8be4-d0b0dd714fed">

<p>RUNNABLE이 높을 경우 &#58; 정상적인 상태이나, CPU 사용량이 비정상적으로 높을 경우 확인해봐야 합니다&#46;</p>

</li>

<li id="29d14586-24d5-410b-a6f2-81d7268eb765">

<p>BLOCKED가 높을 경우 &#58; Lock 상태의 쓰레드이므로 원인을 파악해봅니다&#46;</p>

</li>

<li id="e6927bea-c36f-4321-9dd9-afea15a57653">

<p>WAITING / TIMED&#95;WAITING &#58; 문제되지 않아요&#46;</p>

</li>

</ul>
