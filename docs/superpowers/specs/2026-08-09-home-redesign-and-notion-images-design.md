# 홈 재설계 + Notion 이미지 연동 — 설계

작성일: 2026-08-09
상태: 초안 (사용자 리뷰 대기)

## 0. 한 줄 요약

기존 홈(`src/pages/index.astro`)의 **배열은 유지**하고 블록별 디테일을 다듬는다.
핵심은 글 커버·썸네일을 실제 콘텐츠에 맞게 채우는 것. 단, 실제 콘텐츠는
brainbackdoor.com(Notion/oopy)에 있고 **대부분 커버가 없는 텍스트+이모지 글**이라,
"첫 인라인 이미지 자동 커버 + 이모지 fallback" 전략을 쓴다.

## 1. 배경에서 확인된 사실 (이번 조사)

- 라이브 사이트는 Notion 기반(oopy 렌더). 홈은 이모지 아이콘 + 텍스트, 글 목록은 제목+날짜뿐.
- 대표 최신글 `SpringCamp 2026 후기`조차 **페이지 커버 없음** — 아이콘은 로봇 이모지, 본문은 인라인 스크린샷.
- 글은 20편 이상(회고·인프라·실습 가이드 위주).
- oopy CDN 이미지는 서명·만료 없는 URL로 **curl 다운로드 가능**함(파이프라인 검증됨).
- 이 Astro repo의 글은 샘플 3편뿐 — Notion 글과 별개. 실제 커버가 뜨려면 글이 이 repo로 와야 함.
- `public/activities/`에 활동 이미지 27장이 이미 있음(about이 사용). 일부는 "지금 하는 일" 썸네일로 재사용 가능.

## 2. 두 트랙 (의존 관계)

- **트랙 A — 홈 디자인**: 배열 유지, 블록별 디테일. 코드는 fallback 포함해 지금도 완성 가능.
- **트랙 B — Notion 콘텐츠 확보(실용 노선)**: 큰 정식 마이그레이션이 아니라,
  "사이트에서 긁을 수 있는 건 긁고, 없는 건 사용자가 직접 전달". A가 실데이터로 마감되려면 B가 선행.

## 3. 홈 디자인 결정 (확정)

배열 순서 불변: 히어로 → 이달의 글 + 사이드바(지금 하는 일) → 카테고리 → 최근 글.

### 3.1 이달의 글 (featured) — 커버 채우기
- 회색 빈 박스 + 거대 워터마크 제거. `post.image`가 있으면 그 이미지로 박스를 채운다.
- 카테고리 라벨(위) → 제목 → 설명 → 날짜·읽기시간(현재 구조 유지).

### 3.2 최근 글 — 썸네일 + 카테고리 위치 (안 B1)
- 각 행: `[썸네일 52px, radius 10px] · [카테고리 라벨↕제목] · [날짜]`.
- 카테고리를 별도 컬럼에서 **제목 위 작은 라벨로 세로 결합**(B1). 시작점을 썸네일 하나로 통일.
- featured의 위계(카테고리 위→제목)와 일치.

### 3.3 지금 하는 일 (사이드바) — 디테일 + 썸네일
- 각 항목에 **썸네일(38px, radius 9px)** 추가. `CurrentItem`에 `image` 필드 추가.
- **↗ 매 행 반복 제거** → 블록 하단 "소개에서 더 보기 →" 링크 하나로 통합.
- 라벨 앞 **파인 그린 점** 하나(히어로 강조점과 같은 언어 = "현재 진행 중").
- 개수 3~8 견고성: 항목이 늘면 행 높이·폰트를 살짝 조여 featured 옆에서 넘치지 않게.
- 보유 로고: NEXTSTEP=`nextstep.webp`, 인프라공방=`inflabang.webp`. 없음: 그란데클립·하린이 육아 → 사용자 제공 또는 이모지.

### 3.4 이미지 전략 (전 블록 공통) — 첫 인라인 이미지 자동 커버
- 각 글의 `image`는 **본문 첫 인라인 이미지**를 자동 커버로 채운다(다운로드하여 `public/covers/`).
- 이미지가 없으면 **이모지 fallback**: Notion 페이지 아이콘(이모지)을 중립 배경 타일에 얹어 썸네일 대체.
- 즉 featured·최근 글·사이드바 모두 "이미지 있으면 이미지, 없으면 이모지" 규칙.

### 3.5 카테고리 (블록 3) — 잠정
- 글 0인 카테고리는 홈에서 **숨김**(또는 비활성 연한 톤). 이전 후에는 4종 모두 글이 생기므로 자연 해소.

### 3.6 브랜딩 (블록 4) — 잠정, 낮은 우선순위
- 헤더 워드마크 "씨유" vs 히어로 "이동규 · brainbackdoor" 이름 이원화. 추후 한쪽으로 통일 검토.

## 4. 트랙 B — 이미지·콘텐츠 확보 방식

- **소스**: brainbackdoor.com 각 글 페이지(oopy). 본문 첫 인라인 이미지 = 커버 후보, 페이지 아이콘 = 이모지 fallback.
- **다운로드**: oopy CDN URL을 `public/covers/<slug>.<ext>`로 저장(파일별 출처 명시).
- **사용자 제공분**: 그란데클립 로고, 하린이 육아 이미지 등 사이트에 없는 것.
- 글 본문 전체(MDX 변환)까지 옮기는 정식 이전은 이 문서 범위 밖 — 필요 시 별도 계획으로 분리.

## 5. 검증 (repo 규칙)

- `pnpm test` / `pnpm check`(0 errors) / `pnpm build` 통과.
- 모바일 320·375·768px 가로 스크롤 없음. 이미지 없을 때 fallback으로 목록이 깨지지 않음.
- 색·간격은 `@theme` 토큰만. 이미지엔 `loading="lazy"`, 비율 고정(featured 16:9 안팎, 썸네일 정사각).

## 6. 열린 항목 — 목업 리뷰로 확정 (2026-08-09)

전체 홈 조립 목업을 사용자가 승인하며 아래로 확정:

1. **사이드바 썸네일 모양 = 라운드 스퀘어(9px).** 원형 안 씀.
2. **카테고리 = 4종 모두 노출.** 이전 후 전부 글이 생기므로 §3.5 "빈 항목 숨김"은 실질 불필요(방어적 fallback만 유지).
3. **이모지 타일 ↔ 사진 썸네일 혼재 허용.** 통일 강제 안 함 — 사진 있으면 사진, 없으면 이모지.
4. **지금 하는 일 fallback 톤 승인:** 로고 없는 항목은 이니셜 배지(예: 그란데클립 `GC`) 또는 이모지(하린이 `👶`). 사용자가 실제 로고를 주면 교체, 안 주면 fallback 유지 가능.
5. 브랜딩 이름 통일(씨유 vs 이동규)은 낮은 우선순위로 보류.
